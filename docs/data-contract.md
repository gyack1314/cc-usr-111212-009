# 规范编码与范围树

## 冻结 schema

字段以 ``id`` 身份、按声明顺序冻结；类型支持 ``long``（有符号 64 位整数）、
``decimal``（声明 ``scale``，按该 scale 精确转成有符号 64 位定标整数）、
``string``（UTF-8）、``bytes``（规范 base64 输入）、``boolean``、``timestamp``
（UTC 微秒，i64）以及 JSON ``null``。索引绑定 schema 摘要（ID、顺序、类型、
scale、必选性）与编码版本，任一项变化都视为另一份索引。

## 行编码

固定字段顺序；行先写字段数 u32 大端，每个字段先写 ``F`` + 长度 + 字段 ID，
再写该值的类型标记与 u64 大端 payload 长度：

| 标记 | 含义 | payload |
| --- | --- | --- |
| ``N`` | null | 0 字节 |
| ``M`` | 缺可选字段 | 0 字节 |
| ``L`` | long | i64 大端 |
| ``D`` | decimal | i64 定标整数 + i32 scale |
| ``S`` | string | 原 UTF-8，不做 Unicode 归一 |
| ``B`` | bytes | 解码后的原始字节 |
| ``T`` | boolean | 00 / 01 |
| ``U`` | timestamp | UTC 微秒 i64 |

null、空串、缺字段是三种不同的值；缺必选字段、未知字段、类型不符一律拒绝。
decimal 只接受十进制文本或 ``[定标整数, scale]``，拒绝二进制浮点；``1.2``、
``1.20``、``1.200`` 在 scale 2 下都编码为 120，超出声明 scale 的非零小数位拒绝，
不隐式舍入；定标后超 i64 也拒绝。类型标记与长度共同避免组合碰撞。

## 类型序与排序键

比较按 schema 类型值，不按长度前缀字节序：null < 缺失 < 非空；字符串按 Unicode
（UTF-8 字节序等价于码点序），bytes 按无符号字节，decimal 按定标整数，
timestamp 按整数。完整行相等就是完整规范行编码相等。

规范行序是 ``(key_fields 类型值元组, 完整规范行)`` 的类型序；非键列通过完整
规范行参与排序与行摘要。袋排序键与叶摘要流都用这一顺序。

## 冻结边界树

``boundaries`` 由清单冻结，两侧共用同一棵树，不根据任一侧数据推导。首尾必须是
独立哨兵 ``min`` / ``max``，不与字符串同名混同；内部端点是 key_fields 类型值
数组，必须严格递增，零宽区间拒绝。叶节点覆盖左闭右开键区间；父节点按叶层两两
合并，奇数层末端与显式 empty-child 合并，不复制末叶。叶可以没有行，空区间也有
标准摘要。

## 摘要

- 叶摘要：domain-tag、左闭右开边界、(完整行 SHA256, 计数) 有序流摘要、总行数、
  不同编码数。摘要流按完整规范行序，不按行哈希排序。
- 父摘要：domain-tag、完整覆盖区间、左子摘要、右子摘要（或 empty-child）。
- 索引绑定：编码版本、schema 摘要、边界树摘要、两侧快照标识、源 SHA256 与封存
  段 SHA256。

根相同只表示在 SHA256 抗碰撞假设下规范多重集一致，不称数学上的绝对证明。若
行哈希碰撞对应不同完整编码，行仍按完整编码分组并报告碰撞，不会当作一致。

## 一次遍历、外排与损坏段

每侧源只遍历一次；行校验后按袋排序键压入内存缓冲，缓冲达条目预算即封存成有序
段，段数逼近打开文件上限时先合并。若打开名额不足以形成两路输入合并，摄取阶段
暂不合并（未打开的段只占磁盘），源关闭后在封印阶段统一归并，因此既不会超限
也不会退化成逐段复制。大重复组也外排，不把全部键留在内存。摘要与
差分只读封存段，不重新遍历源；源未完整遍历或清单行数/字节数/SHA256 不符时
不发布根摘要。

段文件为 ASCII 文本，首行 ``BAGSEG4``，逐条 ``计数<TAB>行SHA256<TAB>行编码
十六进制``，末行 ``END<TAB>条目数<TAB>段体SHA256``。读取时流式校验，损坏段
直接报错，绝不当作空区间。

## 下钻与袋差分

根不同时从根递归下钻，只对摘要不同的叶或空槽展开原行。每段做完整有序袋差分：
两侧封存段按同一规范行序流式归并，输出按完整行序，列出 ``only_left``、
``only_right``、``count`` 及左右计数与差值；同键不同值只列两侧各自存在的行，
不推测修改前后配对。结论与比较顺序无关，可据 ``ordered_diff_sha256`` 独立重算。
根相同时小资料另用 Counter 交叉核对，仅作核对基准，不作为大流正式算法。
